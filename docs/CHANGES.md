# Change control

The plan changes in exactly three ways. Anything else is a note in `LOG.md`, not a change.

1. **A gate cannot pass without a change.** One paragraph here: date, gate, what blocks it,
   the smallest change that unblocks it, cost in days or dollars. Then make the change.
   Never swap a tool because another looks better.
2. **A risk's fallback fires.** Record which row of the risk table fired and that its
   fallback was applied. No new decision needed.
3. **Interviews start.** Declare v0.1 at the last passed gate, write the resume lines
   earned, continue the remaining phases as v0.2 on the same schedule shifted by the
   interruption. Scope does not change.

Explicitly not changes: CrewAI, LlamaIndex, DSPy, LangSmith, Phoenix, a second cloud, voice,
a repair-cost estimator, legal form filling, auth, multi-tenancy, a chat interface, a second
document type. Those go in `LOG.md` under "ideas for v0.3".
